# Third-Party Notices

RevvySwarm is Revenium's own software, but the compiled macOS application
bundles a number of open-source components: Go packages that are statically
linked into the `revvy-swarm` CLI/TUI binary and into the RevvySwarm desktop
app binary, plus JavaScript packages that are compiled into the desktop app's
bundled web frontend. Each of those components remains under its own
original license, reproduced in full below, and each retains its own
copyright. This file exists to satisfy the attribution and license-text
requirements of the MIT, BSD, and Apache-2.0 licenses that cover nearly all
of them, as required whenever a binary built from them is distributed.

Nothing in this file changes the license under which RevvySwarm itself is
distributed.

## Summary

- **No copyleft components found.** Every dependency below is MIT,
  BSD-2-Clause, BSD-3-Clause, or Apache-2.0 — all permissive licenses that
  are compatible with proprietary/binary distribution and impose no
  requirement to disclose Revenium's own source code. There is no GPL,
  LGPL, AGPL, MPL, SSPL, or similarly-licensed component anywhere in the
  dependency graph that was checked (see Method below).
- **No unlicensed components found.** Every component listed has a
  discoverable license file and/or `license` field in its package manifest.
- **Go**: 25 components linked into the CLI/TUI binary
  (`revvy-swarm`, root module) + 21 components linked into the
  desktop app binary (`cmd/revvy-swarm-desktop` module) — many shared between
  the two, so the true unique-package count is lower; see the two tables below.
- **npm**: 13 components compiled into the desktop app's bundled frontend
  (10 direct `dependencies` plus 3 packages they pull in transitively:
  `scheduler`, `loose-envify`, `js-tokens`).

## Method

**Go.** Both Go modules were analyzed with
[`google/go-licenses`](https://github.com/google/go-licenses)
(`go-licenses csv <package>`), backed by manual verification with
`go list -deps` against the actual `GOOS=darwin GOARCH=arm64` build (matching
the machine that signs/notarizes releases per this repo's `README.md`).

- The root module (`go.mod` at the repo root, module
  `github.com/revenium/revvy-swarm`) was scanned as `./...` — this is the
  source of the `revvy-swarm` CLI/TUI binary.
- The desktop module (`cmd/revvy-swarm-desktop/go.mod`) was scanned as `.`
  with `GOFLAGS=-tags=desktop,production`, matching the tags Wails' own
  `wails build` applies. **This mattered**: without those tags, `go list`
  under-reports — several real dependencies (`github.com/samber/lo`,
  `github.com/pkg/browser`, `github.com/tkrajina/go-reflector`,
  `github.com/wailsapp/mimetype`, `golang.org/x/net/html`, `golang.org/x/text`)
  are only pulled in under the `production` build tag and would otherwise be
  missed.
- **Test-only dependencies were excluded.** `go-licenses` by default resolves
  only the packages a normal (non-test) build needs, so packages that are
  only ever imported by `_test.go` files never appear in its report. This was
  cross-checked against `go list -m all`, which additionally lists
  test/tool-only modules pulled in transitively via `go.sum`
  (`github.com/stretchr/testify`, `github.com/stretchr/objx`,
  `github.com/davecgh/go-spew`, `github.com/pmezard/go-difflib`,
  `gopkg.in/yaml.v3`, `golang.org/x/tools`, `golang.org/x/mod`, and others) —
  none of those appear in the `go-licenses` output or in `go list -deps`
  against the real build, confirming they are test/tooling-only and are not
  linked into either shipped binary, so they are excluded from this file.
  Similarly, `github.com/leaanthony/gosod` (an indirect dependency in
  `cmd/revvy-swarm-desktop/go.mod`) does not appear in the darwin production
  build's dependency graph and is excluded for the same reason.
- Platform-specific dependencies that only apply to Windows or Linux builds
  of Wails (e.g. `github.com/go-ole/go-ole`, `github.com/jchv/go-winloader`,
  `github.com/godbus/dbus/v5`) and dependencies of Wails' `dev`-mode server
  (e.g. `github.com/labstack/echo/v4`) were confirmed absent from the darwin
  build's dependency graph and are excluded, since only the macOS `.app` is
  in scope here.
- License texts were taken directly from each module's copy in the local Go
  module cache (`go env GOMODCACHE`), i.e. the exact source that was
  compiled, rather than fetched fresh from the internet.

**npm.** `npm ls --omit=dev --all` was run against
`cmd/revvy-swarm-desktop/frontend` to get the full **production** dependency
tree (the 10 packages in `package.json`'s `dependencies`, plus whatever they
pull in transitively). Every `devDependency` (Vite, Vitest, ESLint,
Playwright, Testing Library, TypeScript, jsdom, etc.) was checked against the
actual source (`grep` for imports outside test files, plus `vite.config.js`)
and confirmed to be build/test tooling only, never imported by app code — and
this was independently verified by running the real production build
(`npm run build`) and confirming no dev-only package source or identifying
banner ended up in the emitted bundle. License text for each of the 13
production packages was read from its own `LICENSE`/`LICENSE.txt` file inside
`node_modules`, i.e. the exact source that was bundled.

**Wails runtime.** The Wails v2 Go library (`github.com/wailsapp/wails/v2`,
MIT) is what actually runs the embedded webview and drives the frontend, and
is covered in the Go desktop-module table below. Its generated JS/TS runtime
bindings under `cmd/revvy-swarm-desktop/frontend/wailsjs/runtime/` are
Wails' own generated code, not a separately-versioned npm package, so they
are covered by that same Wails MIT license rather than listed again in the
npm table.

**Everything else bundled in the `.app`.** `cmd/revvy-swarm-desktop/build/`
(app icons, `Info.plist`, entitlements, Windows installer scaffolding) and
`wails.json` were checked for embedded third-party binaries or assets with
their own licenses; the only `go:embed` in the desktop module is
`all:frontend/dist` (the built frontend, already covered above). Nothing else
with a separate license is bundled into the `.app`.
